## 2. How defaults are sourced (design §2 mirrored, single source)

`gui2/defaults.py` is the ONLY place a default value lives. `OBJECT_DEFAULTS` /
`ENV_DEFAULTS` are built from a shared `BASE_TRAINING` dict = the validated WP-S1 stack
(dense_init · mono_depth 0.05 · erank 0.01@7k · gated-LPIPS 0.2 · pose_opt · antialiased ·
c2f; MCMC 3M; 30k; planar OFF). Modes differ only in delivery (`extract_object`
True/SH3 for objects, False/SH2 for scenes). `DETAIL_MODE_OVERRIDES` = {target_mp 15,
pose_opt OFF} (WP-N1). The Advanced drawer is generated by iterating `SETTINGS` and
seeding each control from `defaults_for(mode, detail)`; "Reset to recommended" and
mode/detail switches re-seed from the same function. The runner maps the drawer dict to
the trainer via `assemble_training_extra` (keys = `GsplatBackend.get_default_config`
keys) and to delivery via `assemble_delivery_flags`.

**Byte-for-byte check (smoke, all 4 combos object/env × detail on/off):**
`_collect_settings(mode, detail, *_seed_values(mode, detail)) == defaults_for(mode, detail)`
→ **True** (persisted `defaults_byte_for_byte: true`).

## 4. Deviations / notes (honest)

- **Pause not implemented (documented).** Windows has no reliable SIGSTOP for the trainer
  subprocess, so Step② ships **Cancel + resume-from-stage** instead (`runner.cancel()`
  terminates the current subprocess + `backend.request_stop()`; `RunConfig.resume=True`
  skips stages whose on-disk artifacts already exist). This matches the WP note.
- **Screenshots** replaced by HTTP-serve verification + the persisted QC histogram +
  the precise design spec (no browser automation available).
- **Smoke-harness bug found & fixed (not a product bug):** the FIRST smoke run lacked an
  `if __name__ == '__main__'` guard, so hloc's Windows-spawn DataLoader workers
  re-imported and re-executed the whole harness (fork-bomb of extra runners). Fixed by
  guarding the harness (mirrors `_dataset/SONY_TEST/run_sfm_sony.py`). The real app is
  already safe — `run2.py` is guarded, and Gradio spawns the runner in a thread of the
  guarded `__main__`. Re-ran clean.
- **`_after_processing` refactor:** the env-skip nav policy was a closure inside
  `create_app()` (untestable). Extracted to module-level `app.next_step_after_processing(mode)`
  and unit-verified — a genuine improvement that makes the skip logic the single source.
- **`_latest_ckpt` correctness fix:** picks the checkpoint by **numeric** step (not lexical
  sort, which would pick `ckpt_6999` over `ckpt_29999`). Runner-local; does not touch
  shared code.
- **GPU coordination honored:** WP-T2's `SONY_TEST/output_t2` 30k run (PID confirmed by
  cmdline) was never touched; the botched first-run cleanup killed ONLY processes whose
  command line matched `UI1_SMOKE`.

**Dedicated CANCEL/RESUME GATE — PASS** (evidence: `_infusion/ui1_cancel_gate.json`;
driver `scratchpad/ui1_cancel_gate.py`; run on the free GPU, WP-T2 never touched — the
process matcher requires `UI1_CANCEL` in the cmdline):
- **A) cancel mid-training → resume:** cancelled at frac 0.20 with `ckpt_374_rank0.pt`
  present; `status_after_cancel=cancelled`, **orphan_trainers=[]** (no orphan); resume
  **skipped features/matching/reconstruction/export**, **warm-started from the checkpoint**
  (`resume_warm_start_in_trainer_log=true` — trainer logged `[Init] … from checkpoint
  ckpt_374…`, and the runner logged `[resume] warm-start from ckpt_374…`), and completed
  with **2 deliverables**. So resume no longer restarts from step 0. **PASS.**
- **B) cancel mid-delivery during self-refit:** the nested self-refit trainer (PID 39540)
  was confirmed LIVE during delivery, then cancel **tree-killed** it →
  `status=cancelled`, **orphan_trainers=[]** (nested trainer died with its parent), GPU
  freed. **PASS.**

**HIGH #1 — resume restarts from step 0 → FIXED** (`gui2/runner.py` training stage).
On `resume`, pick the latest checkpoint numerically, warm-start via `--init_ckpt`, and
train only the REMAINING steps (`eff_max_steps = max_steps − done_steps`). Verified the
trainer's `--init_ckpt` is a WARM-START (step counter restarts at 1), so we also pass
`--refine_stop_iter = remaining` (init_ckpt otherwise defaults `refine_stop=1` = no MCMC
growth) and disable coarse on a warm model. If the checkpoint is already at `max_steps`,
training is skipped (reuse). Enabling fix below.
- **Enabling backend fix (gated, no legacy change):** the trainer's `--save_steps` is
  `nargs="*"`, but `GsplatBackend.train` passed a SEPARATE `--save_steps` flag per step,
  so argparse kept only the LAST → **only the final checkpoint was ever written** (so a
  mid-training cancel had nothing to resume from). Fixed behind an opt-in
  `extra["save_all"]`: when set, pass ALL steps as ONE flag (intermediate ckpts written);
  when absent (every legacy caller), the old per-flag loop is byte-identical — so the
  legacy GUI's lexical `sorted()[-1]` ckpt/PLY selection can't regress. gui2 sets
  `save_all=True` + quarterly `save_steps` and selects ckpts numerically (`_latest_ckpt`).

**HIGH #2 — cancel during delivery orphans the nested refit trainer → FIXED.**
`gui2/runner._terminate_tree()` kills the whole process TREE (Windows `taskkill /T /F`;
psutil-children fallback elsewhere) + `terminate()→wait(timeout)→kill()` escalation. Used
in `cancel()` and the delivery cancel branch. Also hardened two cancel-path races found
while gating: (a) re-check cancel right after `backend.train()` (a terminated trainer can
EOF the stdout stream and RETURN normally instead of raising), and (b) a tree-killed
delivery's non-zero exit is surfaced as _cancelled_, not _failed_.

**HIGH #3 — cancel/resume gate written + run:** see above (PASS).

**MED #4 — `filter_harmonics` was a dead drawer lever → FIXED.**
`assemble_delivery_flags` now emits `--filter_harmonics <v>` (was relying on delivery's
coincidentally-matching fallback). Round-trip assertion added to the gate
(`delivery_flag_roundtrip_ok=true`: object→SH3, env→SH2, changing it changes the flag).

**MED #5 — `auto_data_factor` picked by sqrt-rounding, not nearest-MP → FIXED.**
Now brute-forces f∈1..8 minimizing `|source/f² − target_mp|`, tiebreak toward the smaller
factor. Verified (persisted `auto_data_factor_ok=true`): **12→2, 36→3, 10→2, 60→3, 24→2,
8→1, 8.29(4K)→1, 60@15(detail)→2** (was 12→1, 36→2, 10→1 under the old rounding).

**MED #6 — mode/detail toggles clobbered manual Advanced edits → FIXED (documented).**
Mode change now updates ONLY the two mode-intrinsic drawer fields (`extract_object`,
`filter_harmonics`); Detail change updates ONLY `target_mp` + `pose_opt`; all other manual
edits are preserved, with a note. "Reset to recommended" remains the explicit full reload.

**MED #7 — double-start / global-runner guard → FIXED.** Start is refused while
`_RUNNER.is_alive()` with an "a scan is already running" notice. Two-tabs-two-scans is
documented as out of scope for UI-1.
